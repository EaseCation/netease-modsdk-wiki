将官方 Git 仓库和 MCP 原始文档快照同步到本项目，恢复附件，并完成站点构建验证。

## 同步入口

```bash
npm run docs:sync
```

默认更新 `mc-netease-sdk`、`netease-bedrock-wiki`、`modsdk_mcp_server` 三个官方 Git 仓库的缓存。可以通过 `--sdk-source PATH`、`--wiki-source PATH`、`--mcp-source PATH` 显式指定只读本机快照；`--cache-dir PATH` 指定缓存目录。显式快照不会自动 pull，输出会标明所用提交。

## 来源优先级

- SDK 仓库提供 API、Apollo 和预设文档基础版本。
- 教程仓库提供 mcguide、mconline 及原始附件。
- MCP 的 docs/ 提供 API 与官方审核文档补充；根据 source_url 映射目标路径，按 last_modified 与基础页面 Git 修改时间择新。无日期的 MCP 页面仅补缺。
- 保留镜像中来源日期更晚的页面，避免切换来源造成版本回退。MCP input/ 中的旧教程不覆盖独立教程仓库。
- Git 日期仅是缺少官网日期时的保守比较依据。同步完成不代表官网实时抓取，只代表所列上游快照完成合并。

## 附件与失败处理

脚本先在暂存目录合并文档，再检查附件，最后才写入工作区：

1. LFS 指针优先从本地镜像、相邻仓库和 Git LFS 对象缓存恢复，必须同时匹配 SHA-256 与大小。
2. 缺失附件尝试固定提交的 GitHub 媒体地址和官网地址。
3. 官网附件被打包成带哈希的文件名时，读取对应原文网页中的实际引用；只接受唯一的文件名对应项。
4. HTTP 200 的 HTML 错误页、空文件和残留 LFS 指针均不能冒充附件。
5. 无法恢复时退出失败并列出路径和引用页面，不会应用本次文档变更。不要通过忽略错误、删除引用或伪造空附件来宣称同步完成。

来源和附件回执位于 Git 目录的 sync-docs-state.json。原始字节备份位于 sync-docs-backup/，未完成的恢复现场不得覆盖。暂存目录正常结束时清理，上游 Git 缓存可复用。若手动中断导致暂存残留，仅清理确认属于本任务且不再运行的目录。

## 构建验证

```bash
npm run docs:build
```

构建使用 package.json 配置的 8 GB 堆上限。检查实际退出码及构建结果，不以被 tail 管道掩盖的状态判断成功。构建仅验证站点产物，不冒称游戏功能验收。

VitePress 配置保留上游 HTML/Vue 兼容转换。附件检查由同步脚本负责，构建时的缺失资源兜底不能替代附件验收。

## 输出

说明使用的上游提交、选用的 MCP 页面、实际新增/修改/删除数量、附件恢复情况和构建结果。保留工作区供检查，不自动提交、推送、发布站点或上传 Algolia 索引；这些外部操作按用户当次授权执行。
